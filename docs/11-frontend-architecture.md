# 11 — Frontend Architecture

Next.js 14 App Router + TypeScript (versions from the recovered build: `next@14.2`, `react@18.3`, `typescript@5.8`). Styling is **CSS Modules + CSS custom properties** (no Tailwind — not in the dependency set). The production app decomposes the prototype into the components in `05`; it does **not** paste prototype HTML into one component.

## Rendering strategy

- **Marketing + `/invite/[token]`:** Server Components, mostly static/ISR; great SEO + fast first paint. The 3D canvas and interactive bits are client components mounted lazily.
- **Auth pages:** server-rendered shells with client forms.
- **`/app/*`:** server layout enforces session (redirect to `/login?next=`); pages are client-driven via React Query for live data. Initial data can be prefetched in the server component and hydrated.

## Routing & auth handling

- Route groups `(marketing)`/`(auth)`/`app` isolate layouts.
- `middleware.ts`: resolve locale (next-intl) and gate `/app/*` (no session → redirect). Authorization (ownership/roles) is **not** done here — the API owns it; the UI just reacts to `401/403/404`.
- Current celebration (`eventId`) kept in a small client context + URL/searchparam, hydrated from `GET /events`.

## State management

- **Server state:** React Query only (caching, mutations, optimistic updates, invalidation). No Redux/Zustand.
- **Local/UI state:** React state + a couple of contexts (`ThemeContext`, `CurrentEventContext`, `LocaleProvider`). Theme persists to `localStorage` + `data-theme` (matches prototype).
- **Forms:** react-hook-form + zod; schemas shared with validation lib; submit via generated mutation hooks.

## API client

- `orval` generates typed React Query hooks from `openapi.yaml`. Single fetch wrapper adds credentials (cookie), CSRF header, and normalizes the error envelope into typed errors. 401 → redirect to login; 403/404 → route-level error/empty states.

## Animation architecture

- `lib/motion` wraps `framer-motion` + IntersectionObserver to provide the `04` primitives (`Reveal`, `Magnetic`, `Tilt`, section grading, grain). All read `prefers-reduced-motion` and pointer capability once via a provider.
- `lib/three` dynamically imports three.js + the invitation module; renders poster image until ready / on reduced-motion / no WebGL; pauses rAF offscreen.

## Styling conventions

- Tokens defined once in `globals.css` (`:root` light, `:root[data-theme=dark]`, `@media (prefers-reduced-motion)`), consumed via `var(--…)`.
- Component styles in colocated `*.module.css` mirroring the recovered `ds_*`/`marketing_*` rules. Use `color-mix(in srgb, …)` as the prototype does.
- No utility-class framework; shared layout helpers as small modules.

## Asset handling

- Logo lockups/symbols per theme from `assets/`; served via `next/image` where raster.
- Prototype `shots/*.jpg` reused as 3D posters / template previews.
- Inline SVG icon set (arch, dot, nav) as components.

## Error / loading / empty

Every data view supplies `Skeleton` (loading), `EmptyState` (no data), `ErrorState` (retry). Suspense/`loading.tsx` + `error.tsx` per route segment. Detailed mapping in `12`.

## Performance

Code splitting per route group; lazy three.js; `next/font`; `next/image` optimization; memoize expensive lists; avoid layout thrashing in motion (transform/opacity only); disable heavy effects on mobile/low-power (see `04`).
